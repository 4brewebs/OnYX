# onyx-workspace

**Workspace coding tools, EAV side-effect ledger, mode policies, OS sandboxing, Sprout local service orchestration, and Git tree checkpoints for harnesses built on `onyx-soul-agents`.**

Provides sandboxed filesystem, Git inspection, AST outline/impact (`onyx-scent`), local process/container orchestration (`sprout.toml`), and shell execution capabilities that plug directly into `onyx-soul-agents` as a `PlatformDriver` bridge, keeping external I/O out of deterministic `OnyxSystem`s and preserving diskless `Transcript` replay.

## Components

- `WorkspacePolicy`, `PermissionRules` & `PermissionDecision`:
  - Canonicalizes `root` on disk and blocks path escapes (`..` or symlinks outside `root`) via `resolve_existing` and `resolve_for_write`.
  - Skips `ignored_dirs` (`.git`, `target`, `node_modules`), `.onyx/vault/` session storage, and runtime snapshot/transcript artifacts (`snapshots/`, `snaps_*`, `*.tr`, `*.onyxpack`, `tick-*.bin`) by default.
  - Enforces default I/O limits (`max_read_bytes = 64 KiB`, `max_output_bytes = 32 KiB`, `command_timeout = 30s`, configurable via `WorkspacePolicy::with_command_timeout`).
  - Loads declarative `[permissions]` rules (`deny`, `allow`, `ask`), `[sandbox]` settings (`mode`, `network`, `env_passthrough`, `allow_read_paths`, `max_memory_mb`, `max_pids`, `container_image`), and `[impact]` settings (`enabled`, `max_hops`, `ask_heat_bp`, `hard_ask_bp` for monotonic *Scent-Heated Approval* `Allow → Ask` in `impact.rs`) from `~/.onyx/config.toml` and `<workspace>/.onyx/config.toml` (`with_loaded_config` / `with_permissions` / `with_sandbox` / `with_impact` / `with_ignore_deny`) with precedence `deny > ask > allow`; global `deny` rules cannot be removed by project config, `WorkspaceMode::Plan` / `Explore` unconditionally block mutating tools, and Control Plane files (`.onyx/config.toml`, `.onyx/vault/**`, `.git/hooks/**`, `.git/config`, `.env*`) are protected read-only (`check_control_plane_write`).
- Workspace Trust (`trust.rs`):
  - Computes `blake3` hashes of `<workspace>/.onyx/config.toml` and `<workspace>/sprout.toml` against `~/.onyx/trusted_workspaces.toml` (overridable via `ONYX_TRUST_FILE`), returning `NoProjectConfig`, `Trusted`, `Untrusted`, or `Modified`.
  - When a repository is `Untrusted` or `Modified`, restrictive merging ignores project-level `allow`, `env_passthrough`, `allow_read_paths`, `container_image`, and any `[sandbox]`/`[impact]` relaxation while keeping `deny`, `ask`, and stricter limits active, and blocks `SproutSupervisor` mutating operations (`start`, `start_all`, `stop`, `exec_in_container`) until explicitly trusted.
- LLM Profiles (`llm_profile.rs`):
  - Parses `[[llm_profiles]]` blocks from `.onyx/config.toml` (fields: `id`, `provider` (`gemini`/`openai`/`anthropic`), `model`, `effort` (`auto`/`low`/`medium`/`high`), optional `api_base`, optional `api_key_env`). Unknown or duplicate keys are actionable parse errors; a literal `api_key` is rejected with an error pointing to `api_key_env` (the value is never echoed).
  - Untrusted workspaces ignore `[[llm_profiles]]` (actionable warning); trusted ones merge with *replace-by-id* precedence `global < workspace`. `public_snapshot()` exposes metadata only (provider, model, effort, availability reason) — never keys.
  - The active target is projected into the EAV graph as `ws.llm.profile` / `ws.llm.provider` / `ws.llm.model` / `ws.llm.effort` so snapshots and `ONYXTR2` transcripts are self-contained from tick 0.
- External CLI Drivers (`external_driver.rs`):
  - Parses `[[external_drivers]]` blocks (fields: `id` (`[a-z0-9_-]`), `bin`, `args`, `prompt_transport` (`stdin` default / `arg` / `temp_file`), `prompt_flag`, `timeout_secs`, `allowed_env`, `inherit_home`, `network_allowlist`). `prompt_transport = "arg"` is rejected on Windows when `bin` resolves to a `.cmd`/`.bat` wrapper.
  - `external_driver_gate` (`policy.rs`): untrusted workspaces get absolute `Deny`; without specific rules `spawn_subagent(<driver>)` defaults to `Ask` (never falls through to the Allow fallback), with per-driver specificity `deny > ask > allow`.
  - Derived network policy: empty `network_allowlist` → `LocalhostOnly`; a declared allowlist skips `*_OFFLINE` injection (the harness must reach its API). Enforcement is `StrictContainer`-only; advisory under the other profiles.
- MCP Client (`mcp.rs`):
  - 0-deps parser for `[mcp.servers.<name>]` blocks in `config.toml` (fields: `transport` (`"stdio"` with `command`/`args`/`env`, or `"http"` with `url`/`headers`), `timeout_secs` (default `20`), `enabled` (default `true`)); server names cannot contain `__` (reserved for the tool prefix); `${ENV_VAR}` references expand only at launch time (never logged/persisted) and `Authorization`/`X-Api-Key` headers require `${VAR}`.
  - *Replace-by-name* merge with precedence `global < workspace (trusted)`; an untrusted workspace ignores its `[mcp.servers.*]` with an actionable warning mentioning `openonyx trust` / `--trust-workspace`.
  - JSON-RPC 2.0 transport: stdio with a dedicated reader thread, real per-call `mpsc::recv_timeout`, a 4 MiB `stdout` line cap, and `ProcessJob` tree teardown on failure (Windows & Unix); Streamable HTTP (`initialize` → `notifications/initialized` → `tools/list` → `tools/call`) with persistent `Mcp-Session-Id` and paginated `tools/list` (max 16 pages).
  - Dynamic tools are exposed to the LLM as `mcp__<server>__<tool>` with `requires_approval = true` (`policy.rs` forces `Deny` for `mcp__*` in `Plan`/`Explore`); results and errors pass through `truncate_utf8` + `scrub_secrets`; a dead server isolates to `Failed(msg)` without aborting the session, and each server exposes `McpServerStatus` for `openonyx doctor`.
- OS Sandbox & RAII Process Supervision (`sandbox.rs`):
  - `SandboxMode` (`Off`, `WorkspaceWrite` default, `StrictContainer`), `SandboxMode::effective_badge(driver)` (`workspace` on Linux `bwrap` / macOS `sandbox-exec`, `env+job` on Windows `Win32Job`, `env+pgid` when no FS/net driver is active, `strict`, `off`), `NetworkPolicy` (`Offline` default, `LocalhostOnly`, `Unrestricted`), and `SandboxConfig::elevate_for_auto_approve`.
  - Strict OCI validation (`ContainerCli { Docker, Nerdctl, Podman }`, `validate_oci_image_ref`) preventing flag injection through `container_image` or `container_cli`.
  - Strict environment sanitization (`apply_sanitized_env`): starts with `env_clear()`, strips all sensitive keys (`*_API_KEY`, `*_TOKEN`, `AWS_*`, etc.), redirects `TMP`/`TEMP`/`TMPDIR` to a session-scoped temp dir, and injects offline tool hints (`CARGO_NET_OFFLINE`, `PIP_NO_INDEX`, `NPM_CONFIG_OFFLINE`).
  - Cross-platform `ProcessJob` (`std::process::Child`, zero `tokio`): Win32 Job Objects (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, memory/PID limits) on Windows and POSIX `PGID` termination on Unix, shared by both `shell_exec` and `onyx-sprout` (SDD-08).
  - Native OS driver selection (`bwrap` with live `bwrap_is_usable()` probe to fall back gracefully on Linux hosts where AppArmor blocks unprivileged user namespaces, `landlock`, `sandbox-exec`, `win32-job`, OCI `docker`/`nerdctl`/`podman`), pre-execution offline network command blocking, and `detect_sandbox_capabilities()` for `openonyx doctor`.
- `WorkspaceTools` & `ToolSchema`:
  - `fs_read` — read UTF-8 files (optional 1-based `start_line` / `end_line` range), with `recall_seen` session deduplication (`@TOON v1` `unchanged_since_tick:<N>` and overlapping/subset range deduplication `covered_by:<start>-<end>`), actionable error messages when pointed at binary OnYX artifacts (`ONYXTR1`, `ONYXTR2`, `ONYXPK1`, `ONYXAG`), and automatic invalidation on `fs_write`, `fs_edit`, `shell_exec`, or `/undo` (`clear_seen_reads`).
  - `fs_list` — list directory entries up to `max_depth` (default `3`), ignoring symlinks and ignored directories.
  - `fs_write` — create or overwrite a UTF-8 file *(requires approval by default)*.
  - `fs_edit` — unique exact replacement (`old_text`/`new_text`) or atomic sequential multi-hunk `edits: [{ old_text, new_text }]` applied in memory before writing, with line-trimmed fallback and automatic relative indentation adjustment *(requires approval by default)*.
  - `code_search` — literal or `regex` search across workspace files with optional `case_insensitive`, `include_glob`, `exclude_glob`, `context_lines` (`0..=5` grouped hunks), secret scrubbing, and symlink/ignored-dir skipping *(read-only, no approval required)*.
  - `glob_files` — read-only workspace file discovery matching glob patterns (`*`, `**`, `?`, `[...]`, `{a,b}`) with deterministic lexicographical order (or optional `sort_by_mtime`), path-traversal rejection, and ignored-directory filtering *(no approval required)*.
  - `git_status` — concise `git status --short --branch` inspection *(read-only, no approval required)*.
  - `git_diff` — unified `git diff --no-color` inspection with optional relative `path` (passed strictly after `--`), `staged`, and `context_lines` *(read-only, no approval required)*.
  - `load_skill` — on-demand protocol/guide loader (`SKILL.md` / `*.md` from `<workspace>/.onyx/skills/`, `<workspace>/skills/`, `~/.onyx/skills/`, plus built-in `scent` and `rust` guides) paired with `discover_skills_summary` *(read-only, no approval required)*.
  - `plan_update` — structured progress checklist (`[x]`, `[>]`, `[ ]` + optional `explanation`) persisted to the EAV graph via `ws.plan.text` (`set_workspace_plan`, `graph_workspace_plan`, `format_plan_steps`) *(no approval required)*.
  - `scent_outline` / `scent_impact` *(optional `feature = "scent"`)* — read-only AST outline and semantic call-impact tools backed by `onyx-scent` (`blake3` incremental cache + per-session `seen_outlines` deduplication automatically invalidated on file edits, `shell_exec`, or `/undo`, plus `@TOON v1` paginated output with `public_only`, `exclude_tests`, and `max_rows` clamped `1..=500`), validated through `WorkspacePolicy` *(no approval required)*.
  - `shell_exec` — execute a shell command inside `root` with timeout, full process-tree cleanup, concurrent stdout/stderr draining, credential scrubbing (`scrub_secrets`), output limits, and automatic `clear_seen_reads()` *(requires approval by default)*.
  - `service_status`, `service_start`, `service_stop`, `service_logs`, `service_exec` (`sprout.rs`, SDD-08) — local process & OCI container (`ContainerCli`: `docker`/`nerdctl`/`podman`) DAG orchestrator backed by `sprout.toml` (`[runtime]`/`[services.<id>]` and legacy `[global]`/`[[service]]`), validated container names & opt-in `exec_user`, Workspace Trust enforcement (`[UNTRUSTED — run /trust]` blocking mutating actions until trusted), real readiness probes (`ready_port`, `ready_log`, `ready_cmd`), bounded UTF-8-lossy log ring-buffers, `env_clear()`, Win32/POSIX `ProcessJob` teardown on `Drop`, and `ws.services.text` EAV graph projection (`service_status`/`service_logs` read-only; `service_start`/`service_stop`/`service_exec` require approval and are blocked in `Plan`/`Explore`).
  - `preview_tool_diff(root, tool, args_json, max_lines)` — pure unified diff preview generator for single- and multi-hunk `fs_edit` / `fs_write` reusing line-trimmed matching and relative re-indentation.
   - `spawn_subagent` / `subagent_status` / `subagent_merge` / `subagent_discard` (`worktree.rs`, SDD-10) — async subagent jobs in isolated Git worktrees (base dir from explicit override / `ONYX_WT_DIR`, else sibling `<parent>/.onyx-wt/<name>`, falling back to temp `onyx-wt/<name>`; branch `onyx/sub/<job_id>`; ephemeral base commit). Parallelism capped by `with_max_concurrent`. `spawn_subagent` takes `goal` (required), `max_steps` (default `32`, max `128`), and an optional `driver` (`native` or an `[[external_drivers]]` id). `subagent_merge` previews the 3-way `git merge-tree` (`preview_three_way_merge` → `apply_clean_merge`) without moving `HEAD` or the index, and `classify_merge_delta` classifies the delta before anything touches disk (Control Plane → `Deny` blocks the entire merge; `sprout.toml` / `.github/workflows/**` → `Ask`; rest → impact-based `Safe`; external drivers force `Ask` via `ExternalDriverApprovalPolicy`). Job state is projected to the EAV graph as `ws.subagent.job_id` / `driver` / `branch` / `status` / `ok` / `spawn_tick` / `summary` / `touched_files`. Merging requires Git `>= 2.38.0`.
  - `WorkspaceTools::schemas()` / `schemas_with_subagents(true)` — export JSON parameter schemas for LLM function calling.
- `WorkspaceMode`, `WorkspaceLedgerSystem` & Transactional Undo (`state.rs`):
  - `WorkspaceMode` (`Plan`, `Build`, `Explore`), thread-safe `WorkspaceModeHandle`, and graph-backed `ws.mode` (`set_workspace_mode`, `graph_workspace_mode`).
  - Tracks `File` nodes (`ws.file.path`, `ws.file.read_tick`, `ws.file.dirty`) and `ExternalEffect` nodes (`ws.effect.*`, `ws.effect.undone`, `effects_after_tick`, `latest_undoable_effect`, `mark_latest_effect_undone`, `undone_effects`).
  - Lightweight Git checkpoints: `capture_git_tree_checkpoint` writes a temporary `GIT_INDEX_FILE` (`git add -A` + `git write-tree`, supporting repositories both with commits and with an unborn `HEAD`) without mutating `HEAD` or the user's staging area; `restore_git_tree_checkpoint` and `restore_git_tree_checkpoint_for_targets` run `git read-tree --reset -u <tree_sha>`, remove newly created untracked target files that did not exist in `tree_sha` (preserving unrelated user untracked files), and reset `.git/index` back to `HEAD` when `HEAD` exists.
- `WorkspaceToolBridge` (`bridge.rs`):
  - Implements `PlatformDriver` wrapping an inner driver (`HeadlessDriver`, `CliApprovalDriver`, or `TuiDriver`).
  - Reads mode from graph (`ws.mode`, falling back to `WorkspaceModeHandle`), enforces `require_read_before_edit`, and evaluates `PermissionRules` (`evaluate_permission_in_mode`) both on `WaitingApproval` (auto-approving `Allow`, auto-denying `Deny` or read-only mode, signaling wakeups via `with_ready_flag`) and on `Acting` (enforcing `deny` even when `--auto-approve` is active).
  - Captures pre-mutation Git checkpoints for `fs_write`/`fs_edit`, records them in `PendingCheckpoints`, and embeds `[checkpoint:<head>:<tree>]` in `Reply::observe` so `WorkspaceLedgerSystem` reconstructs `ws.effect.tree_sha` deterministically even during diskless `ReplayBridge` playback.
  - Materializes `undone_effects` in `present()` (avoiding double-execution on resumed graphs via `sync_existing_undos`), keeping `OnyxSystem`s free of disk/Git I/O.
